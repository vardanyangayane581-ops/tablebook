# Tablebook

Սեղանի ամրագրում փոքր սրճարանների համար։ Հյուրը կարող է գրանցվել և մուտք գործել իր հաշիվ։

## Ինչ է պետք

- **Node.js 22.13 կամ ավելի նոր** տարբերակ (ստուգել՝ `node -v`)։ SQLite-ը Node-ի մեջ ներկառուցված է (`node:sqlite`), առանձին տեղադրել պետք չէ։

## Գործարկում

1. Տեղադրեք փաթեթները.
   ```bash
   npm install
   ```
2. Պատճենեք `.env.example` ֆայլը `.env` անունով և `SESSION_SECRET=`-ից հետո գրեք երկար պատահական բանալի։ Բանալի ստանալու համար՝
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   Առանց `SESSION_SECRET`-ի սերվերը չի գործարկվի և կասի, թե ինչ անել։
3. Գործարկեք սերվերը.
   ```bash
   npm start
   ```
4. Բացեք բրաուզերում՝ http://localhost:3000

Առաջին գործարկման ժամանակ սերվերը ինքն է ստեղծում `data/tablebook.db` բազան `db/schema.sql` ֆայլից։ Դատարկ բազայով սկսելու համար կանգնեցրեք սերվերը (Ctrl + C), ջնջեք `data/tablebook.db`-ն և նորից գործարկեք։

Կոնսոլում կարող է երևալ `ExperimentalWarning: SQLite is an experimental feature`։ Դա սխալ չէ։

Էջը բացեք `http://localhost:3000` հասցեով, ոչ թե `index.html` ֆայլի վրա կրկնակի սեղմելով, այլապես գրանցումը և մուտքը չեն աշխատի։

## Էջեր

- `/` — գլխավոր էջ, վերևում «Մուտք» և «Գրանցվել» հղումներով
- `/register` — գրանցում
- `/login` — մուտք

Ճիշտ գրանցումից կամ մուտքից հետո հյուրը անցնում է գլխավոր էջ, որտեղ հղումների փոխարեն երևում են «Բարև, Անուն»-ը և «Դուրս գալ» կոճակը։

## Ֆայլերի կառուցվածքը

```
tablebook/
├── server.js            Express սերվերը և API-ն
├── package.json         Փաթեթներ՝ express, express-session, bcryptjs
├── .env.example         Կարգավորումների օրինակ (առանց իրական արժեքների)
├── db/
│   └── schema.sql       users աղյուսակի CREATE TABLE հրամանը
├── data/
│   └── tablebook.db     Տվյալների բազան (ստեղծվում է ավտոմատ, git-ում չէ)
└── public/
    ├── index.html       Գլխավոր էջը
    ├── register.html    Գրանցման էջը
    ├── login.html       Մուտքի էջը
    ├── style.css        Բոլոր էջերի ոճերը
    ├── theme.js         «Փոխել թեման» կոճակը
    ├── validation.js    Ստուգումներ և սխալների տեքստեր (սերվերն ու էջը օգտագործում են նույն ֆայլը)
    └── auth.js          Ձևերի ուղարկում և սխալների ցուցադրում
```

## API

| Մեթոդ | Հասցե | Ինչ է անում |
|---|---|---|
| POST | `/api/register` | Գրանցում (`first_name`, `last_name`, `email`, `telephone`, `password`) |
| POST | `/api/login` | Մուտք (`email`, `password`) |
| GET | `/api/me` | Մուտք գործած օգտատերը կամ `null` |
| POST | `/api/logout` | Դուրս գալ՝ ջնջում է սեսիան |

Սխալների դեպքում պատասխանը `{ "errors": { "դաշտի_անուն": "տեքստ" } }` տեսքի է։

## Անվտանգություն

- Գաղտնաբառը բաց տեքստով չի պահվում։ Բազայում պահվում է միայն `bcryptjs` հեշը (12 ռաունդ)։
- Գաղտնաբառը և հեշը չեն գրվում կոնսոլում և չեն վերադարձվում սերվերի պատասխաններում։
- SQL-ի բոլոր հարցումները պարամետրացված են (prepared statements)։
- Մուտքը պահվում է սերվերի սեսիայով (`express-session`), `httpOnly` cookie-ով։ Սեսիաները պահվում են սերվերի հիշողության մեջ, այնպես որ վերագործարկելուց հետո պետք է նորից մուտք գործել։
- Ստուգումները կատարվում են սերվերում, իսկ էջում՝ միայն հարմարության համար։

## Ռեստորաններ, զամբյուղ և ադմին վահանակ

- `/restaurants` — ռեստորանների ցանկ՝ որոնումով և խոհանոցի զտիչով
- `/restaurant?id=N` — ռեստորանի մենյուն՝ բաժիններով, «+ Ավելացնել» կոճակով
- `/cart` — զամբյուղ․ ուտեստները դասավորվում են որպես երեկոյի ճաշացանկ, հյուրը ընտրում է օրը, ժամը և հաստատում
- `/my-menus` — հյուրի հաստատած ճաշացանկերը և նրանց կարգավիճակը
- `/admin-login` — ադմին վահանակի մուտք, `/admin` — վահանակը

Ադմին վահանակ կարող է մուտք գործել **միայն մեկ աշխատող**, որի տվյալները նշված են `.env` ֆայլում (`ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, օրինակը՝ `.env.example`-ում)։ Բազայում `admins` աղյուսակը թույլ չի տալիս երկրորդ աշխատող։ Ցանկացած այլ անձ (այդ թվում գրանցված հաճախորդ) ստանում է սխալ, և էջի ներքևում գրվում է, որ տվյալ անձը չի կարող մուտք գործել ադմին վահանակ։ 15 րոպեում 5 անհաջող փորձից հետո մուտքը ժամանակավորապես արգելափակվում է։

Վահանակում աշխատողը կարող է՝
- ավելացնել, խմբագրել, թաքցնել և ջնջել ռեստորաններ
- կառավարել յուրաքանչյուր ռեստորանի մենյուն (ուտեստ, բաժին, գին, էմոջի, հասանելիություն)
- հաստատել կամ մերժել հաճախորդների ճաշացանկերը
- փոխել գլխավոր էջի տեքստերը և հայտարարությունը

Բոլոր ռեստորանները, մենյուները, հասցեները և հեռախոսները օրինակային են (`db/seed.js`) և ավելացվում են առաջին գործարկման ժամանակ։ Զամբյուղը պահվում է բրաուզերում, իսկ գներն ու անունները սերվերը միշտ նորից վերցնում է բազայից։
